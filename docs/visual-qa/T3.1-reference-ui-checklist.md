# T3.1 Reference UI Visual QA Checklist

Use this checklist against the supplied reference recordings and curated frames. Capture evidence at the same viewport classes used by the existing app evidence: primary desktop, standard desktop, laptop, and mobile.

## Fidelity

- [ ] Three-zone composition, proportions, spacing, and information density track the reference.
- [ ] Typography, contrast ladder, borders, controls, geometry, and accent usage match the reference character.
- [ ] Graph/radial treatment, orbit hierarchy, node scale, labels, and edge visibility match the intended reference state.
- [ ] Rails and inspector have the same structural weight and attention hierarchy as the reference.
- [ ] Empty or sparse regions remain intentional; no fabricated density or decorative filler.

## Interaction states

- [ ] Resting state is legible and stable.
- [ ] Search attenuates the world and highlights matches in place.
- [ ] Selection reveals the relevant neighbourhood and inspector detail.
- [ ] Relationship rows expose verb, direction, confidence, and expandable provenance where applicable.
- [ ] Transitions are purposeful, bounded, and do not change object identity or layout unexpectedly.

## DEVWORKSPACE translation

- [ ] Reference-specific branding, labels, and content are translated to the developer-workspace domain.
- [ ] No new product capability, entity, or workflow is introduced solely to imitate the reference.
- [ ] Real developer-oriented data and existing cross-surface object identity are preserved.

## Responsive and accessibility checks

- [ ] Desktop, laptop, and mobile compositions remain usable without accidental overflow or occlusion.
- [ ] Keyboard focus, readable text, and non-colour meaning survive every tested state.
- [ ] Reduced-motion mode removes continuous motion without information loss.

## Evidence gate

- [ ] Screenshots are captured for resting, search, selected/inspected, and at least one responsive state.
- [ ] Console/runtime errors and failing tests are recorded before completion.
- [ ] Compare against both the reference assets and the existing `app/docs/screenshots/` evidence; do not replace either source.
